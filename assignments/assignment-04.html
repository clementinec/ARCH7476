Assignment 4: Evidence-Backed Design Workflow Package

Retrospective Redesign or Live Studio Application

Due: End of Week 12
Weight: 40%
Format: Final package plus presentation and reproducibility capsule

Note

A4 is an assembly of work developed through A1-A3. It should not be restarted from scratch in Weeks 10-12.

Purpose

A4 is the final synthesis of the course.

You will show how one design decision has been improved by one evidence-backed generative workflow.

Choose One Route

Route A: Retrospective Redesign

Use a past studio project.

Show how the decision would be rebuilt with better evidence, clearer variables, a stronger workflow, and a more defensible recommendation.

Route B: Live Studio Application

Use a current studio project.

Show how the workflow supported, challenged, changed, or narrowed an active design decision.

Guardrail

A4 is not a whole studio presentation.

It is:

one design decision improved by one evidence-backed generative workflow.

Session 2 Check-Ins That Feed A4

These check-ins are how the final package is tested in class before submission.

Week Bring to Session 2 Round-table question A4 component
9 figure, output table, comparison chart, or object-card draft What result changes the design action, and what uncertainty remains visible? Practice Case + Object Card
10 draft presentation, object card, package outline, or reproducibility capsule index Can a reviewer trace decision -> variants/scenarios -> workflow -> output -> threshold -> limit? Draft Package
11 weakest A4 component or the component most in need of peer review Which A4 component is weakest, and what must be fixed before submission? Final Package
12 final object card or reflection note What design reasoning can transfer to another studio project? Reflection Note

Use the Project Reasoning Check-In template if you want a consistent note structure.

Required Components

1. Practice Case

Format: 2 slides
Audience: studio critic, client, practice reviewer, or project stakeholder

Must include:

  • decision
  • variants or scenarios compared
  • evidence output
  • recommendation
  • threshold or comparison rule
  • limit / caveat

2. Research Brief

Length: 2 pages

Must include:

  • question
  • workflow route
  • input sources
  • method steps
  • variants/scenarios generated or compared
  • output
  • uncertainty
  • interpretation
  • what remains unresolved

3. Object Card

Format: 1 page

Must show:

  • dominant figure
  • design decision
  • key evidence
  • threshold or comparison
  • recommendation or next action

4. Reproducibility Capsule

Submit a small folder or ZIP that another person can actually re-run:

  • README with step-by-step run instructions
  • environment / dependency list (tools and versions; e.g. requirements.txt or a stated software list)
  • data dictionary or source list
  • the runnable workflow artifact (script, workbook, project, or notebook — not only a screenshot)
  • figure sources, plus a one-line note confirming that re-running reproduces the key figure
  • AI prompt log if relevant
  • verification notes

5. Feedback + Revision Ledger

Show how critique changed the workflow or design decision.

Include at least three entries:

Feedback source What it challenged What changed What did not change, and why
peer / instructor / tool output / AI check assumption, metric, threshold, figure, route, or claim revision made reason for rejecting or deferring

The point is not to obey every comment. The point is to show judgment about which feedback made the workflow more testable.

6. Reflection Note

Length: 1 page

Answer:

  • What did the workflow change?
  • What did it not resolve?
  • What would you do next?
  • How could this workflow transfer to another studio project?

Route-Specific Requirements

Route A: Retrospective Redesign

Include:

  • original decision and original evidence logic
  • rebuilt workflow
  • what the workflow would have changed
  • revised design recommendation

Route B: Live Studio Application

Include:

  • current studio decision
  • why the decision matters now
  • how the workflow affected the live project
  • next studio action

Assessment Criteria

Criterion Weight
Decision clarity 15%
Generative workflow execution 20%
Evidence quality and uncertainty 20%
Design impact 15%
Reproducibility — the capsule re-runs 15%
Feedback/revision judgment 10%
Documentation and communication clarity 5%

What Counts as Design Impact

Design impact can mean:

  • changed the scheme
  • confirmed a decision
  • rejected an option
  • narrowed a parameter range
  • clarified what evidence is still missing
  • changed how the student would argue the decision

Common Failure Modes

  • presenting the whole studio project instead of one decision
  • hiding the workflow behind polished images
  • making stronger claims than the evidence supports
  • submitting AI-assisted material without verification
  • treating feedback as a checklist instead of a judgment problem
  • leaving the threshold or recommendation vague

Use the Final Package Checklist before submission.
