ARCH7476: Evidence-Based Generative Design

Tool Pathways for Studio Decisions

Course Overview

ARCH7476 is a mixed-cohort course for architecture students who need a clearer way to move from intuition to evidence. The course now starts by making the tool landscape explicit, then asks each student to choose one primary pathway for the semester:

  • Spreadsheet for transparent low-code comparison, charting, and decision matrices
  • GIS for spatial evidence, map-based reasoning, and geospatial workflows
  • Python for notebook-based analysis, scripting, and reproducible evidence building

The course keeps BIM/BEM and building performance as shared literacy for everyone, but the assessed semester pathway is chosen from spreadsheet, GIS, or Python.

What Students Leave With

By the end of the semester, students will be able to:

  1. Frame a design decision as an evidence problem rather than a vague preference
  2. Audit what counted as evidence in a prior project and identify missing evidence
  3. Choose a tool pathway that actually fits the decision being made
  4. Run one primary workflow with enough independence to keep using it after the course
  5. Communicate findings with clear limits, confidence, and next steps for studio or practice

Mixed-Cohort Design

This course is designed for undergraduates, MArch students, and occasional PhD students in the same room.

Student level What stays common What scales by level
Undergraduate Same weekly structure and assignments More scaffolding, narrower scope, simpler analysis
MArch Same weekly structure and assignments Stronger stakeholder fit, more independence, practice-ready outputs
PhD Same weekly structure and assignments Higher rigor, deeper uncertainty treatment, stronger reproducibility

The difference is depth and independence, not separate coursework.

Semester Structure

Phase 1: Survey the Landscape

Weeks 1-5 introduce the tool families and the decisions they support:

  • spreadsheet workflows for comparison and traceable reasoning
  • GIS alternatives: QGIS, ArcGIS, and geopandas
  • notebook workflows in Jupyter
  • BIM/BEM and simulation literacy

Phase 2: Choose a Pathway

By the middle of the semester, each student formally chooses one primary pathway and uses it to:

  • define evidence sources
  • prototype a method
  • run a pilot workflow
  • build a studio-facing evidence package

Phase 3: Apply It to Studio

The back half of the semester focuses on:

  • evidence quality and uncertainty
  • decision thresholds
  • visual communication
  • workflow documentation
  • transfer into the next studio project

Tool Pathways

Spreadsheet Pathway

Best for students who need a strong, professional baseline without heavy setup.

  • organize precedent and observation data
  • compare alternatives
  • build uncertainty-aware charts
  • produce decision matrices and summary tables

GIS Pathway

Best for site analysis, urban context, access, zoning, and spatial comparison.

  • learn when QGIS is the fastest choice
  • understand where ArcGIS fits in practice
  • run a minimal code-based workflow in geopandas
  • connect map outputs back to architectural decisions

Python Pathway

Best for students who need more automation, reuse, or analytical control.

  • work in Jupyter Notebook
  • use pandas and plotting for evidence building
  • adapt the provided notebooks to project-specific data
  • document a reproducible workflow others can inspect
Why Spreadsheet Matters

Spreadsheet is the baseline exit pathway for the course. It is not remedial. It is the lowest-friction route to a credible, transparent, decision-ready workflow, and a student can complete the course very well through it.

Setup Guidance

Everyone

  • spreadsheet software: Excel or Google Sheets
  • browser access to course materials and downloads

If You Choose GIS or Python

  • Jupyter Notebook as the main notebook interface
  • Anaconda or Miniconda as the supported local Python environment
  • Google Colab as the no-install fallback

See Resources for the setup ladder and tool chooser.

Course Position

This course is not trying to turn every architecture student into a software specialist. It is trying to make tool choice, evidence quality, and decision logic explicit enough that students can justify design moves with more than instinct.
