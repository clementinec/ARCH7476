A2 Worked Example: Facade Shading for a Campus Reading Room

When the best design depends on which metric you trust

NoteAbout This Example

This is a worked A2 skeleton based on a common architectural design problem: choosing a facade shading strategy using daylight and energy simulation. Unlike the Hidden Drivers example, this one starts from a spatial design decision — the kind of question a studio project would produce. The structure is the same; the evidence is different.

1. Decision Recap

Decision

Which shading strategy for the south-facing reading room of a proposed campus library produces acceptable daylight while keeping cooling loads within the project’s energy budget?

Alternatives

Option Description
A — Fixed horizontal louvers 600 mm deep aluminum louvers at 450 mm spacing, fixed angle
B — Perforated metal screen 40% perforation ratio, flush-mounted, no moving parts
C — Automated roller blinds Interior fabric blinds activated by exterior illuminance sensor at 25 klux

All three options share the same glazing (double low-e, SHGC 0.27) and the same floor plan. Only the shading device changes.

Audience

Design team and client sustainability consultant, who will use the comparison to select one system for the schematic design package.

Why evidence matters

The team’s instinct favours Option A (louvers — familiar, low maintenance). But the reading room faces due south in a subtropical climate (Hong Kong), and the consultant has flagged that fixed louvers may over-shade the space in winter, reducing useful daylight below the 300 lux threshold for reading. The choice cannot rest on instinct alone because the three options perform differently on daylight, glare, and cooling — and the ranking changes depending on which metric leads.

What action the evidence should support

Select one shading system for the schematic design submission, with documented evidence showing the trade-off between daylight, glare, and energy for each option.

LEED v4 / IES LM-83 Standard Medium — defines daylight metrics (sDA, ASE) Public High Metrics are annual summaries — do not capture seasonal variation Threshold for daylight acceptability

What is missing from this evidence map

  • Post-occupancy data from a comparable reading room with each shading type
  • Occupant preference data (do readers actually prefer 300 lux or more?)
  • Maintenance and cost data (relevant to the final decision, but outside the simulation scope)
  • Glare assessment from an occupant position (DGP, not just illuminance)

Route Selection

I am choosing Grasshopper + Ladybug/Honeybee because my decision depends on comparing spatially resolved annual daylight and cooling load for three shading options on the same geometry, and the minimum useful output is sDA, ASE, and annual cooling EUI for each option.

Risk Check

  • Most fragile input: Optical properties of the perforated screen (Option B) — manufacturer data gives a single perforation ratio, but angular transmittance is not specified
  • Likely setup problem: Getting Honeybee’s Radiance material definitions to match the shading products; ensuring the EnergyPlus shading schedule for Option C (automated blinds) triggers correctly
  • What I can cut: Drop DGP (glare probability) and report only sDA/ASE — glare requires a separate point-in-time simulation for each view direction
  • What I need help with: Validating that the Radiance material for the perforated screen is a reasonable approximation

Workflow definition

  • Input files: Rhino .3dm with reading-room geometry; Hong Kong .epw; three Grasshopper shading component definitions
  • Variable: Shading option (A / B / C) — the only thing that changes between runs
  • Steps: Model setup → apply each shading option → run annual daylight (Radiance) → run annual energy (EnergyPlus) → extract sDA, ASE, cooling EUI → compare against thresholds → rank
  • Expected output: Comparison table with pass/fail per metric; spatial daylight maps for each option; recommendation with stated trade-off
  • Threshold: sDA ≥ 55%, ASE ≤ 10%, cooling EUI ≤ project target
  • Likely failure point: Option B’s angular transmittance — if the Radiance material is wrong, the daylight results for the perforated screen are unreliable

5. A4 Branch Declaration

Route

Route B: Live Studio Application — this facade decision is part of an active studio project, and the simulation results will feed directly into the schematic design submission.

Decision

  • Project: Campus library — south-facing reading room
  • Decision: Which shading system to specify for the south facade
  • Alternatives: Fixed louvers (A), perforated screen (B), automated blinds (C)
  • Why this matters: The choice affects both the occupant experience (daylight, glare) and the project’s energy budget — and the ranking depends on which metric leads

Workflow

  • Primary route: Grasshopper + Ladybug/Honeybee
  • Input files: Rhino model, EPW, shading definitions
  • What varies: Shading device (single controlled variable)
  • Minimum scenarios: 3 (one per option) + 1 sensitivity run (threshold ± 10%)
  • Output: sDA, ASE, cooling EUI per option; comparison table; spatial daylight maps
  • Threshold: sDA ≥ 55%, ASE ≤ 10%, cooling EUI ≤ project target

Feasibility

  • What must exist by A3: Working Honeybee model producing sDA and cooling EUI for at least Options A and C (the two with well-defined material properties)
  • Most likely failure: Perforated screen material definition (Option B) — if angular transmittance cannot be modeled reliably, drop B and compare A vs. C only
  • Backup route: If Honeybee simulation is too slow or fails to converge, fall back to Climate Studio or a simplified Radiance-only daylight comparison without the energy model
  • What can be simplified: Drop the spatial daylight maps and report only the aggregate sDA percentage

Branch Statement

I will use Route B (Live Studio Application) to test which shading strategy meets both daylight and cooling thresholds for the reading room, through a controlled comparison of three facade options simulated under identical conditions, because the design decision depends on a trade-off the team cannot resolve by instinct — the option that wins on daylight may lose on energy — and the minimum useful output is a comparison table showing sDA, ASE, and cooling EUI for each option against pre-stated thresholds.

Why This Example Works as an A2

  1. The decision is spatial and architectural. It starts from a facade, a room, an orientation — not a dataset. The simulation serves the design question.

  2. The ranking is not obvious. Option A (the team’s instinct) may fail on daylight. Option B scores well on daylight but costs more energy. Option C passes everything but requires maintenance and control logic. The evidence does not point to one winner — it reveals a trade-off the team must negotiate.

  3. The controlled variable is clear. Only the shading device changes. Geometry, climate file, glazing, occupancy schedule, and simulation settings are held fixed.

  4. Thresholds are stated before the simulation runs. sDA ≥ 55%, ASE ≤ 10%, cooling EUI ≤ target. This prevents the post-hoc narrative of “well, 47% is close enough.”

  5. The weakest link is named. The perforated screen’s angular transmittance is flagged as the most fragile input, with a stated backup plan (drop Option B).

  6. The tool choice follows the question. Grasshopper + Honeybee is chosen because the question requires spatially resolved annual daylight and annual energy on the same geometry — not because it is the most advanced option. The spreadsheet route is explicitly rejected because it cannot capture seasonal shading geometry effects.

TipAdapting This to Your Studio Project

You do not need a facade study. Replace the shading options with any set of design alternatives you are comparing:

  • Three site layouts → GIS or Grasshopper, evaluated by walkability, noise exposure, or solar access
  • Three structural systems → BIM/BEM, evaluated by embodied carbon, span, or construction sequence
  • Three ventilation strategies → EnergyPlus or CFD, evaluated by air change rate, energy use, or thermal comfort

Keep the structure: one controlled variable, same evaluation method, stated thresholds, named weakest input, and a comparison table where the ranking might change depending on which metric leads. That tension is what makes the evidence useful.
