Assignment 3: Workflow Prototype + Verification

Generate or Compare Variants, Then Verify the Output

Due: End of Week 9
Weight: 25%
Format: PDF submission plus workflow artifact

Purpose

A3 is where the workflow becomes real.

You will build the smallest working version of your chosen workflow, generate or compare multiple variants/scenarios, produce one output, and document how you verified or debugged it.

Core Question

Can this workflow generate or compare variants and produce an output that helps the design decision?

Session 2 Check-Ins That Feed A3

These check-ins should make the prototype visible before the deadline. Bring rough artifacts; the point is to expose workflow reasoning early.

Week Bring to Session 2 Round-table question A3 component
7 workflow artifact, GH canvas, notebook output, spreadsheet, GIS map, simulation screenshot, or AI-assisted component What goes in, what varies, what comes out, and what quality check proves it ran? Prototype Scope + Workflow Description
8 prompt log, error message, output, README fragment, verification note, or workflow checklist What must someone else inspect before they trust this output? Verification and Failure Log
9 figure, output table, comparison chart, or object-card draft What result changes the design action, and what uncertainty remains visible? Prototype Output + threshold language

Use the Project Reasoning Check-In template if you want a consistent note structure.

Required Components

1. Prototype Scope

Define:

  • design decision
  • workflow route
  • input sources
  • variable or range
  • minimum of three variants, scenarios, or alternatives
  • output target
  • what is intentionally out of scope

2. Workflow Artifact

Submit the relevant artifact:

  • GH definition or screenshots/export
  • simulation setup or preset output
  • GIS project output and supporting files
  • Python notebook or exported notebook
  • spreadsheet workbook
  • AI-assisted generated component plus verification notes

3. Workflow Description

Explain the workflow in inspectable steps.

Use this structure:

  1. input
  2. operation
  3. output
  4. quality check
  5. design interpretation

4. Generative Loop

Show the loop:

  1. input condition
  2. variable/range
  3. variants, scenarios, or alternatives
  4. evaluation metric
  5. output
  6. threshold or comparison rule
  7. design action

5. Prototype Output

Show one interpretable output from the workflow.

Examples:

  • variant comparison
  • map or spatial summary
  • daylight/solar/energy result
  • parameter table
  • chart with ranges
  • generated script/component with verified result

6. Verification and Failure Log

Document:

  • what worked
  • what failed
  • what you checked manually
  • what assumption matters most
  • what remains untrusted

If AI assisted any part of the workflow, include the AI Workflow Verification Card.

Assessment Criteria

Criterion Weight
Generative loop coherence 30%
Utility of variant/scenario output 25%
Verification and debugging 20%
Treatment of uncertainty 15%
Documentation quality 10%

Differentiated Expectations

Undergraduate

  • small but complete workflow
  • clear explanation
  • honest failure log

MArch

  • stronger connection between output and studio decision
  • more independent troubleshooting
  • output should inform a real design action

RPg / PhD

  • sharper method rationale
  • stronger reproducibility
  • deeper uncertainty treatment

Common Failure Modes

  • submitting screenshots without workflow logic
  • building a tool artifact that answers no decision question
  • hiding broken steps
  • using AI-generated code without verification
  • treating one weak output as final proof

# Purpose

`A3` is where the workflow becomes real.

You will build the smallest working version of your chosen workflow, generate or compare multiple variants/scenarios, produce one output, and document how you verified or debugged it.

# Core Question

> Can this workflow generate or compare variants and produce an output that helps the design decision?

# Session 2 Check-Ins That Feed A3

These check-ins should make the prototype visible before the deadline. Bring rough artifacts; the point is to expose workflow reasoning early.

| Week | Bring to Session 2 | Round-table question | A3 component |
|---:|---|---|---|
| 7 | workflow artifact, GH canvas, notebook output, spreadsheet, GIS map, simulation screenshot, or AI-assisted component | What goes in, what varies, what comes out, and what quality check proves it ran? | Prototype Scope + Workflow Description |
| 8 | prompt log, error message, output, README fragment, verification note, or workflow checklist | What must someone else inspect before they trust this output? | Verification and Failure Log |
| 9 | figure, output table, comparison chart, or object-card draft | What result changes the design action, and what uncertainty remains visible? | Prototype Output + threshold language |

Use the [Project Reasoning Check-In](../templates/project-reasoning-checkin.md) template if you want a consistent note structure.

# Required Components

## 1. Prototype Scope

Define:

- design decision
- workflow route
- input sources
- variable or range
- minimum of three variants, scenarios, or alternatives
- output target
- what is intentionally out of scope

## 2. Workflow Artifact

Submit the relevant artifact:

- GH definition or screenshots/export
- simulation setup or preset output
- GIS project output and supporting files
- Python notebook or exported notebook
- spreadsheet workbook
- AI-assisted generated component plus verification notes

## 3. Workflow Description

Explain the workflow in inspectable steps.

Use this structure:

1. input
2. operation
3. output
4. quality check
5. design interpretation

## 4. Generative Loop

Show the loop:

1. input condition
2. variable/range
3. variants, scenarios, or alternatives
4. evaluation metric
5. output
6. threshold or comparison rule
7. design action

## 5. Prototype Output

Show one interpretable output from the workflow.

Examples:

- variant comparison
- map or spatial summary
- daylight/solar/energy result
- parameter table
- chart with ranges
- generated script/component with verified result

## 6. Verification and Failure Log

Document:

- what worked
- what failed
- what you checked manually
- what assumption matters most
- what remains untrusted

If AI assisted any part of the workflow, include the [AI Workflow Verification Card](../templates/ai-workflow-verification-card.md).

# Common Failure Modes

- building a tool artifact that answers no decision question
- hiding broken steps
- using AI-generated code without verification
- treating one weak output as final proof
