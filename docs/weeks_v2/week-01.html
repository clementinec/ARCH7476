Session 1: Lecture / Demo

Today we learn: how a studio decision becomes more defensible when its evidence is made visible.

Why it matters for your studio: you will use one past or current project as the case material for the semester.

The Reset

This course is not primarily organized around software demos.

It is organized around one question:

What evidence would make a design decision more defensible?

Evidence Needs a Workflow

  • precedent images can be useful, but they rarely prove performance on their own
  • simulation numbers can be precise, but they still depend on assumptions
  • survey comments can be rich, but they need context before they generalize
  • data only becomes useful when the path from input to decision is legible

Sometimes Evidence Is Just Vibes

A vibe is not useless.

It is often the first clue that something might matter.

A vibe is not enough by itself.

It becomes stronger when the next step asks what would confirm, qualify, or challenge it.

For each image: name the vibe claim, what it does not show yet, and the next evidence move.

Vibe Case 1: Busy = Working?

Let the class answer first

Vibe claim: “This restaurant layout works; it feels busy.”

What it does not prove yet: atmosphere is not the same as a measured use pattern.

Evidence to ask for: dwell time, table turnover, circulation pinch points, observation by time period.

Vibe Case 2: Polished = High Performance?

This is the ad logic problem

Vibe claim: “This camera is good; the image looks amazing.”

What it does not prove yet: presentation polish is not performance.

Evidence to ask for: controlled comparisons, low-light tests, compression checks, failure cases.

Vibe Case 3: Calm = Safer?

Perception matters, but it is partial

Vibe claim: “This route is safer; it feels calmer.”

What it does not prove yet: perceived calm may miss actual risk.

Evidence to ask for: lighting levels, pedestrian counts, crossing conflicts, crash or incident records, user surveys.

Vibe Case 4: Green = Sustainable?

The studio render problem

Vibe claim: “This facade is sustainable; the render is green and shaded.”

What it does not prove yet: visual greenness is not environmental performance.

Evidence to ask for: solar exposure, heat gain, daylight, irrigation/maintenance, material data.

Architecture Version: Persuasive Images Are a Start

Claim: “This public space strategy works because the precedent photo is lively.”

Limit: the photo may be curated, seasonal, event-based, or taken at peak hour.

Evidence needed: observation schedule, activity mapping, dwell time, user groups, weather/time notes.

In A1, look for one place where your own project used a convincing image, phrase, or precedent before the evidence logic was fully explicit.

The Current Reality in Studio

Decisions are often shaped by:

  • precedent and intuition
  • tutor feedback and design judgment
  • assumptions that were reasonable but not yet tested
  • evidence assembled late in the process

The course is trying to make that process more explicit and more defensible.

The Semester Spine

  1. Recall a past design decision
  2. Identify the evidence and weak links
  3. Translate the decision into variables, ranges, and workflow routes
  4. Generate or compare variants/scenarios
  5. Use evidence to state a threshold and design action

Workflow Routes, Not Software Shopping

  • GH / parametric: vary design options
  • BIM/BEM / simulation: test performance assumptions
  • GIS: compare spatial conditions
  • Python / notebook: rerun analysis and figures
  • AI-assisted workflow: speed up components, then verify
  • Spreadsheet / low-code: compare ranges and thresholds transparently

The course question is not “Which software looks advanced?”
It is “Which workflow makes this decision more defensible?”

The First Question to Ask

Not:

“What software should I use?”

But:

“What evidence would reduce uncertainty around this decision?”

A1 Starts Here

Bring in one prior design decision you already made and believed was evidence-based.

Then ask:

  • what was the decision?
  • what actually counted as evidence?
  • where was confidence stronger than the evidence?
  • what will I need for my next studio decision?

A1 Has Two Moves

Move 1: Audit a prior decision

  • what did you decide?
  • what evidence did you think you had?
  • what was actually doing the work?

Move 2: Set up the next one

  • what decision is coming next?
  • what evidence would actually help?
  • who needs to be convinced?

Round 1: State the Decision Clearly

Each student gives a 60-90 second project statement.

Cover:

  • the prior design decision
  • the alternatives that were on the table
  • why the decision mattered

The room listens for one problem:

  • the decision is too broad
  • the alternatives are unclear
  • the audience is unclear
  • the “evidence” is still vague

Round 2: What Counted as Evidence?

For the same decision, list the actual inputs used at the time:

  • precedent images
  • tutor advice
  • code or standards
  • measurements
  • simulations
  • observations
  • user or stakeholder input
  • assumptions and taste

Do not clean this up yet. Get the real list down first.

Round 3: Sort the Inputs

Now sort those inputs into:

  • evidence strong enough to matter
  • evidence weak but treated as strong
  • assumptions disguised as evidence
  • gaps that were never addressed

The room’s job is to challenge overconfidence without redesigning the project.
