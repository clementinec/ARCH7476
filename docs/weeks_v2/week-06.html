Strategic, not exhaustive

Evidence mapping is a decision, not a collection

You are not collecting everything. You are deciding:

  • what actually matters to this decision
  • what is realistically accessible this semester
  • what is convincing for your audience
  • what your chosen pathway can realistically process

A source earns its place only when it could change the scheme, not decorate the presentation.

Worked pathway claim: Kai Tak

If this were your next studio decision, which evidence sources would actually change the scheme rather than merely decorate the presentation?

Evidence categories to sort

Often decisive

  • published research
  • standards and code
  • site observations
  • open datasets
  • simulations
  • maps and spatial layers

Often supporting only

  • precedent and case studies
  • interviews or surveys
  • one-off articles

Useful for framing, rarely enough on their own.

Not every category belongs in every project.

Triage every source

Ask four questions of each one:

Relevant Does it bear on this decision?

Trustworthy Can the source be inspected and trusted?

Local Is it close enough to your site and program?

Usable Can I actually use it this semester?

A simple source triage table

Source relevance access confidence best use
precedent image set medium easy low-medium framing
planning dataset high medium high site constraints
one-off online article low easy low not enough on its own

The table is the argument: relevance and confidence decide what leads, access decides what is feasible.

The key fork

Two routes, one set of A4 components

Everyone arrives at the same A4 package. You choose how you get there.

One decision, not the whole project You are mapping a pathway for one decision and its smallest useful output — not re-planning your entire studio project.

The fork, side by side

Route A · retrospective redesign

  • start from a past studio board
  • pick one decision you would now redo
  • arrive at a redesigned decision with evidence behind it
  • safest when your current studio is too unsettled to instrument

Route B · live studio application

  • start from your current studio board
  • pick one decision you are facing now
  • arrive at an active design move you can apply this term
  • best when a live decision genuinely depends on the analysis

Both converge on the same A4 components. Pick the route that lets you do honest work now.

Evidence → pathway matrix

Let the kind of evidence that drives your decision point to a pathway.

If the deciding evidence is… …the natural pathway is strongest when
comparison of options and thresholds spreadsheet comparison logic is the core task
location, overlap, spatial reach GIS location drives the decision
repeatable analysis and figures Python repeatability and flexibility matter
families of design options GH / parametric design variables are central
performance under assumptions BIM/BEM / simulation model-based testing is needed
an accelerable, verifiable step AI-assisted the result can be inspected

Compare the pathways directly

Pathway strongest when weak when
spreadsheet comparison logic is the core task the question is deeply spatial or repetitive
GIS location and overlap drive the decision the project barely depends on spatial analysis
Python repeatability and flexible analysis matter setup outweighs the analytical benefit
GH / parametric design variables and option families are central there is no clear evaluation output
BIM/BEM / simulation performance assumptions need model-based testing setup or cleanup exceeds the decision value
AI-assisted a component can be accelerated and verified the result cannot be inspected or reproduced

Pathway contract

A2 has to name the transfer path

Every pathway declaration includes a handoff target. This is what prevents “I chose a tool” from replacing the actual method.

Pathway Export / handoff GH or package bridge
spreadsheet variant_scores.csv read into GH; color/rank variants
GIS site_layers.geojson + score table import context geometry and attributes
Python notebook + exported figure/table feed metrics or plots to package/GH
GH / parametric GH definition + variant log direct geometry variants and CSV metrics
BIM/BEM / proxy scenario table + metrics CSV drive facade/massing revisions
AI-assisted prompt log + verified component GhPython/C# function or documentation block

Pathway choice should feel boring

If the pathway is right, it should feel obvious in hindsight.

Wrong reason “Python seems more impressive.”

Better reason “The question is spatial, and GIS is the shortest path to a useful output.”

Pathway commitment drill

Complete this sentence out loud, then post it:

I am choosing spreadsheet / GIS / Python / GH / BIM-BEM / AI-assisted because my decision depends primarily on ________, and the minimum useful output will be ________.

If you cannot finish the sentence clearly, the pathway is not chosen yet — and that is fine to discover here.

Warning signs

Catch these now

  • too many source types with no hierarchy
  • a pathway choice that does not change the method
  • no clear output format
  • a question still too large for a prototype

Uncertainty check

Choosing a pathway also chooses what you will ignore

Question for A2 What does your chosen pathway make visible, and what does it make almost impossible to see within this semester?

Write both answers into the A2 matrix. The unsupported part becomes a limit, not a hidden weakness.

ML principle connection

Does your route generalize, or only fit this one case?

Principle 6 — Generalization is the goal In ML, a model that is perfect on its training set but fails on new data has overfit. A workflow is the same: it must hold up beyond the single case you tuned it on.

So Pick a route whose smallest useful output would still be defensible on a second site, season, or scenario — not just the one that looks good today.
