Publishing Your Work: GitHub Pages

A Reusable Portfolio Site in 15 Minutes

Why Publish?

Your evidence package is more useful as a live page than a PDF buried in a submission folder.

A published site:

  • lets reviewers, tutors, and peers see your work without downloading anything
  • becomes a portfolio piece you keep after the course ends
  • can host interactive tools (maps, charts) alongside your written analysis
  • proves you can communicate evidence to a real audience, not just submit it

You are building something reusable. Treat it that way.

Step 1: Create a GitHub Account

If you already have a GitHub account (many HKU students do), skip to Step 2.

  1. Go to github.com and click Sign up
  2. Use your HKU email or personal email — either works
  3. Choose a username you are comfortable sharing publicly (it becomes part of your site URL)
  4. Verify your email

Your username determines your site address: https://username.github.io

Step 2: Create Your Site Repository

There are two paths. Choose whichever feels simpler.

Path A: Personal Site (Recommended)

This gives you a site at username.github.io — clean and professional.

  1. On GitHub, click the + in the top-right corner → New repository
  2. Name the repository exactly username.github.io (replace username with your actual GitHub username)
  3. Check Add a README file
  4. Click Create repository
  5. GitHub Pages is automatically enabled for repositories with this naming pattern

Path B: Project Site

This gives you a site at username.github.io/repo-name — useful if you want separate sites for different projects.

  1. Create a new repository with any name (e.g., arch7476-evidence)
  2. Go to the repository → Settings → Pages (in the left sidebar)
  3. Under Source, select Deploy from a branch
  4. Choose main branch, / (root) folder
  5. Click Save

Either way, your site goes live within a minute or two after you add an index.html file.

Step 3: Your First Page

Create a file called index.html in the root of your repository. You can do this directly on GitHub:

  1. In your repository, click Add file → Create new file
  2. Name it index.html
  3. Paste the template below
  4. Click Commit new file

Your site will be live at your GitHub Pages URL within a couple of minutes.

Step 4: Adding the GIS Explorer

The course provides a browser-based GIS analysis tool called gis-explorer.html. To add it to your site:

  1. Download gis-explorer.html from the course repository (site_tools/gis-explorer.html)
  2. In your GitHub repository, click Add file → Upload files
  3. Drag in gis-explorer.html
  4. Commit the upload

Now your evidence package links directly to an interactive map. Visitors click the link and explore your spatial analysis — no install, no download, no Python.

You can also upload your own GeoJSON data files alongside it. The explorer lets users drag-and-drop files directly onto the map.

Step 5: Updating Your Site

Every time you push a change to your repository, GitHub Pages rebuilds the site automatically. There are two ways to make changes:

Edit directly on GitHub (no tools needed)

  1. Navigate to the file in your repository
  2. Click the pencil icon (Edit this file)
  3. Make your changes
  4. Click Commit changes

This works for text edits, adding content, and small fixes.

Use GitHub Desktop (for bigger updates)

  1. Download GitHub Desktop
  2. Clone your repository to your computer
  3. Edit files locally with any text editor
  4. Commit and push from GitHub Desktop

This is better when you are adding images, reorganizing files, or making many changes at once.

Tips

File names

  • Use lowercase, no spaces: site-analysis.png not Site Analysis.png
  • Keep names short and descriptive
  • Use .html for pages, .png or .jpg for images, .geojson for spatial data

Images

  • Resize images before uploading — aim for under 500 KB each
  • Use descriptive alt text for accessibility
  • Place images in the same folder as your index.html or in an images/ subfolder

Keep it simple

  • One page is enough for most projects
  • Do not add a CSS framework or JavaScript library unless you need it
  • The starter template works on phones, tablets, and desktops — test on your phone
  • Focus on the content: decision, evidence, recommendation, limits

What not to publish

  • Do not publish raw data that is not yours to share
  • Do not include personal information about research participants
  • Check with your instructor if you are unsure about a dataset

What You Leave With

After this setup, you have:

  • a live URL you can share with anyone: https://username.github.io
  • a professional-looking evidence package that works on any device
  • an interactive GIS explorer linked from your report
  • a site you own and can update forever — not locked inside a course platform
