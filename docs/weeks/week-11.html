Part 1: Geographic Information Systems for Architecture

🌍 What is GIS?

Geographic Information System

Software for capturing, storing, analyzing, and managing spatial/geographic data

Beyond mapping: GIS is analytical infrastructure for spatial decision-making

📍 GIS: Not Just Digital Cartography

Traditional mapping

  • Representing space visually
  • Static documentation of existing conditions
  • Communication tool

GIS analysis

  • Querying spatial relationships
  • Modeling phenomena over space and time
  • Decision support through spatial reasoning
  • Generating insight from location data

🏛️ Why Architects Need GIS Thinking

Site analysis and selection

  • Environmental context (topography, hydrology, climate)
  • Urban context (infrastructure, demographics, zoning)
  • Accessibility analysis (walksheds, transit proximity)
  • Multi-criteria site evaluation

Performance-based design

  • Solar access and shading studies
  • Microclimate and urban heat island analysis
  • Viewshed and visual impact assessment
  • Noise propagation and acoustic environment

Urban design and planning

  • Neighborhood-scale spatial analysis
  • Infrastructure capacity and service area mapping
  • Growth modeling and scenario planning
  • Public space quality and equity assessment

Parametric urbanism

  • Site data extraction for generative design
  • Context-aware algorithmic design
  • Multi-objective spatial optimization
  • Data-driven master planning

🔧 The Four GIS Paradigms

Approach Philosophy Best For Learning Curve
QGIS Open source, GUI-based Exploration, visualization, standard workflows Moderate
ESRI Suite Industry standard, enterprise Professional practice, collaboration, comprehensive tools Moderate-High
Code-driven Programmatic, reproducible Custom analysis, automation, integration with design tools High
Google Earth Engine Cloud-based, massive data Large-scale environmental analysis, satellite imagery Moderate-High

Approach 1: QGIS (Open Source)

🆓 QGIS: The Community-Driven Option

What it is

  • Free and open source desktop GIS application
  • Cross-platform (Windows, Mac, Linux)
  • Extensible through plugins (Python-based)
  • Active community development

Underlying philosophy

  • Democratic access to spatial analysis tools
  • Transparency in algorithms and processes
  • Community knowledge sharing and collaboration
  • Interoperability through open standards

💪 QGIS Strengths for Architects

Accessibility

  • Zero cost - ideal for students and small practices
  • No licensing barriers for exploration and learning
  • Easy installation and experimentation
  • Extensive free tutorials and community resources

Integration capabilities

  • Reads virtually any spatial data format
  • Strong interoperability with other open source tools
  • Python console for scripting and automation
  • Export to common formats (PDF, PNG, DXF, etc.)

Visualization power

  • Sophisticated cartographic styling
  • Layer blending and transparency controls
  • Print composer for professional map layouts
  • Time-series animation capabilities

Analysis breadth

  • Core spatial analysis tools included
  • GRASS GIS integration for advanced terrain analysis
  • Processing toolbox with hundreds of algorithms
  • Custom workflow automation through graphical modeler

⚠️ QGIS Limitations

Performance at scale

  • Can be slow with very large datasets
  • Less optimized than commercial alternatives
  • Limited cloud/server integration

Professional workflow

  • Less common in professional practice (US)
  • Collaboration challenges if clients use ESRI
  • Fewer industry-specific toolsets
  • UI can be less polished than commercial options

Support

  • Community-based (no guaranteed support)
  • Documentation can lag behind development
  • Plugin quality varies widely

🔄 Typical QGIS Workflow for Architecture

1. Data acquisition

  • Download municipal GIS data (parcels, zoning, infrastructure)
  • Access open data portals (OpenStreetMap, USGS, etc.)
  • Georeferenced CAD drawings or site survey data
  • Satellite/aerial imagery basemaps

2. Exploratory analysis

  • Layer stacking and visual exploration
  • Buffer analysis (walkability, noise impact zones)
  • Spatial queries (find all parcels within X distance of transit)
  • Terrain analysis (slope, aspect, watershed delineation)

3. Visualization and export

  • Create analytical maps for presentations
  • Export site context data for CAD/Rhino
  • Generate PDF map series for reports
  • Extract elevation data for 3D modeling

4. When to stop and switch tools

  • Complex custom analysis → Move to Python/R
  • Integration with parametric design → Move to code-driven approach
  • Professional deliverables requiring ESRI format → Convert to ArcGIS

Approach 3: Code-Driven GIS (geopandas, etc.)

💻 Code-Driven: The Programmatic Approach

What it is

  • Python libraries: geopandas, shapely, rasterio, folium
  • R packages: sf, terra, tmap, leaflet
  • Direct manipulation of spatial data through code
  • Integration with data science ecosystem

Underlying philosophy

  • Reproducibility through scripts
  • Flexibility through programming
  • Integration with analysis and design workflows
  • Automation of repetitive tasks
  • Version control and documentation

🐍 Core Python Geospatial Stack

Data handling

  • geopandas - GeoDataFrames (pandas + geometry)
  • shapely - Geometric operations
  • pyproj - Coordinate system transformations
  • fiona - Reading/writing vector data

Raster processing

  • rasterio - Raster data I/O and processing
  • rasterstats - Zonal statistics
  • numpy - Array-based raster calculations

Visualization

  • matplotlib - Static maps and plots
  • folium - Interactive web maps (Leaflet.js wrapper)
  • contextily - Basemap tiles
  • plotly - Interactive 3D visualization

Analysis

  • scipy.spatial - Spatial algorithms and optimization
  • scikit-learn - Machine learning on spatial data
  • networkx - Network analysis
  • PySAL - Spatial econometrics and statistics

🚀 Code-Driven Strengths for Design Research

Reproducibility

  • Scripts document every step of analysis
  • Version control tracks methodological changes
  • Easy to re-run with updated data
  • Transparent methodology for peer review

Automation

  • Process hundreds of scenarios programmatically
  • Batch process multiple sites or alternatives
  • Schedule regular analysis updates
  • Eliminate repetitive GUI clicking

Integration

  • Direct connection to parametric design tools (Rhino/Grasshopper)
  • Combine GIS with machine learning and optimization
  • Web scraping and API integration for data collection
  • Export directly to design software formats

Customization

  • Write exactly the analysis you need
  • Combine tools in novel ways
  • Implement cutting-edge methods from research
  • Build discipline-specific toolsets

Cost and openness

  • Free and open source
  • No licensing restrictions
  • Use anywhere (laptop, server, cloud)
  • Share code freely with collaborators

⚠️ Code-Driven Limitations

Learning curve

  • Requires programming proficiency
  • Must understand both GIS concepts and coding
  • Debugging can be time-consuming
  • Less intuitive than GUI exploration

Visualization

  • Static maps require more code than GUI tools
  • Cartographic refinement more tedious
  • Professional map layouts require additional tools
  • Less “out of the box” polish

No GUI fallback

  • Can’t “click around” to explore
  • Harder to catch data errors visually
  • Every operation must be scripted
  • Initial exploration slower than QGIS/ESRI

Ecosystem fragmentation

  • Multiple libraries with overlapping functions
  • API changes and deprecation
  • Less cohesive than commercial platforms
  • Requires more troubleshooting skills

🔄 Typical Code-Driven Workflow

1. Data preparation

import geopandas as gpd
import rasterio as rio

# Load vector data
parcels = gpd.read_file("parcels.shp")
transit = gpd.read_file("transit_stops.geojson")

# Load raster data
with rio.open("elevation.tif") as src:
    elevation = src.read(1)

2. Spatial analysis

# Buffer transit stops (400m)
transit_buffers = transit.buffer(400)

# Find parcels within transit buffer
accessible_parcels = parcels[
    parcels.intersects(transit_buffers.unary_union)
]

# Calculate slopes from elevation
slopes = calculate_slope(elevation)

3. Parametric integration

# Export site boundary to Rhino
site_boundary = accessible_parcels.iloc[0].geometry
export_to_rhino_3dm(site_boundary, "site.3dm")

# Create elevation grid for Grasshopper
elevation_grid = extract_grid_for_gh(
    elevation, site_boundary
)
np.save("elevation_grid.npy", elevation_grid)

4. Iterative analysis

# Analyze 100 design alternatives
results = []
for alt in design_alternatives:
    solar_exposure = calculate_solar(alt, elevation)
    view_quality = calculate_views(alt, viewpoints)
    results.append({
        'alternative': alt.id,
        'solar': solar_exposure,
        'views': view_quality
    })

results_df = pd.DataFrame(results)

Approach 4: Google Earth Engine (Cloud Platform)

☁️ Google Earth Engine: Cloud-Scale Geospatial

What it is

  • Cloud-based platform for planetary-scale geospatial analysis
  • Access to petabytes of satellite imagery and geospatial datasets
  • JavaScript or Python API for analysis
  • No local data storage or processing required

Underlying philosophy

  • Bring computation to data (not data to computation)
  • Democratize access to Earth observation data
  • Enable large-scale environmental monitoring
  • Cloud-based collaboration and sharing

🛰️ GEE Strengths for Environmental Design

Massive data catalog

  • Landsat archive (1970s-present): 40+ years of Earth observation
  • Sentinel imagery: High-resolution, frequently updated
  • MODIS, ASTER, and other satellite products
  • Climate data: Temperature, precipitation, vegetation indices
  • Terrain: Global elevation models (SRTM, ALOS)

Cloud processing power

  • Process terabytes of data without local downloads
  • Parallel processing across Google’s infrastructure
  • Time-series analysis across decades
  • Regional to global scale analysis

No local infrastructure needed

  • No massive data downloads
  • No powerful local computer required
  • All processing happens in cloud
  • Export results when ready

Analysis capabilities

  • Multi-temporal analysis (change over time)
  • Machine learning on satellite imagery
  • Climate and environmental modeling
  • Urban heat island analysis
  • Vegetation and land cover classification

⚠️ GEE Limitations

Learning curve

  • Requires JavaScript or Python coding
  • Different mental model (cloud-based, lazy evaluation)
  • GEE-specific API and data structures
  • Debugging can be challenging

Architecture focus

  • Better for regional/environmental analysis than site-scale
  • Less useful for detailed building-scale work
  • Focused on raster (satellite) data, less vector support
  • May be overkill for small site analysis

Data resolution

  • Satellite imagery resolution limits (10m-30m for most free data)
  • Not suitable for detailed site features
  • Temporal resolution varies by satellite
  • Cloud cover can limit usable imagery

Export limitations

  • Processing quotas for free tier
  • Results must be exported (not live integration)
  • Large exports can be slow
  • Limited real-time interaction

🔄 Typical GEE Workflow for Architecture

1. Define study area

// Define site or region of interest
var site = ee.Geometry.Point([114.1095, 22.3964]); // Hong Kong
var region = site.buffer(5000); // 5km radius

2. Load and filter data

// Load Landsat 8 imagery
var imagery = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2')
  .filterBounds(region)
  .filterDate('2020-01-01', '2023-12-31')
  .filter(ee.Filter.lt('CLOUD_COVER', 20));

3. Analyze and compute

// Calculate NDVI (vegetation index)
var ndvi = imagery.map(function(image) {
  return image.normalizedDifference(['SR_B5', 'SR_B4'])
    .rename('NDVI');
});

// Get mean NDVI over time period
var meanNDVI = ndvi.mean();

4. Visualize and export

// Visualize on map
Map.addLayer(meanNDVI, {min: 0, max: 1, palette: ['brown', 'yellow', 'green']});

// Export to Google Drive
Export.image.toDrive({
  image: meanNDVI,
  description: 'site_vegetation_analysis',
  scale: 30,
  region: region
});

🌡️ GEE in Practice: Example Use Case

Scenario: Urban heat island analysis for climate-responsive design

GEE workflow

  1. Load 10 years of Landsat thermal imagery for city
  2. Calculate land surface temperature (LST) for each image
  3. Analyze seasonal and annual LST patterns
  4. Identify urban heat island hotspots
  1. Correlate with land cover (vegetation, built-up areas)
  2. Analyze temporal changes (urbanization impact)
  3. Export heat maps and statistics
  4. Use results to inform site selection and cooling strategies

Output: Climate analysis at city/regional scale informing design decisions

🎓 When to Use GEE

Ideal for

  • Regional climate and environmental analysis
  • Multi-year trend analysis (urban growth, climate change)
  • Large-scale site comparison (dozens of potential sites)
  • Environmental context for master planning
  • Urban heat island and microclimate studies

Not ideal for

  • Detailed site-scale analysis (<100m)
  • Real-time or interactive analysis
  • Building-scale precision
  • Projects requiring immediate results
  • Vector-heavy workflows (parcels, buildings)

Learning path

  • Start with Code Editor (JavaScript, web-based)
  • Use Python API if already familiar with Python
  • Leverage example scripts and tutorials (extensive community)
  • Focus on environmental/climate applications for architecture

🎮 Try It Now: Beginner GEE Example

Get Hong Kong Building Footprints

Copy-paste this into GEE Code Editor (code.earthengine.google.com):

// Define area of interest: HKU campus area
var hku = ee.Geometry.Point([114.1361, 22.2831]);
var area = hku.buffer(500); // 500m radius around HKU

// Center map on area
Map.centerObject(area, 16);

// Add basemap
Map.addLayer(area, {color: 'red'}, 'Study Area');

// Load OpenStreetMap building footprints
// (buildings with height/levels attributes where available)
var buildings = ee.FeatureCollection('GOOGLE/Research/open-buildings/v3/polygons')
  .filterBounds(area);

print('Number of buildings:', buildings.size());
print('First 5 buildings:', buildings.limit(5));

// Visualize buildings
Map.addLayer(buildings, {color: 'blue'}, 'Buildings');

// For OSM building attributes (height, levels), use:
// OpenStreetMap QA Tiles (if available in your region)

What this code does

  1. Defines area: 500m around HKU campus
  2. Centers map: Zooms to your study area
  3. Loads buildings: Google’s Open Buildings dataset
  4. Prints info: Number of buildings and attributes
  5. Visualizes: Shows buildings in blue on map

Next steps:

  • Change coordinates to your site
  • Adjust buffer distance (100m-5000m)
  • Explore building attributes in Console
  • Export results to Google Drive

📡 Satellite Imagery Collections

Landsat (1972-present)

  • 40+ years of Earth observation
  • 30m resolution multispectral
  • Thermal bands for temperature
  • Free and open access
  • Ideal for long-term change analysis

Sentinel (2014-present)

  • European Space Agency satellites
  • 10m resolution optical imagery
  • Frequent revisit (every 5 days)
  • Radar imagery (cloud-penetrating)
  • Excellent for recent detailed analysis

MODIS (2000-present)

  • Daily global coverage
  • Lower resolution (250m-1km)
  • Excellent for climate and vegetation
  • Wide range of products (LST, NDVI, snow cover)

🎯 Hands-On: Extract HK Building Data with GEE

Complete workflow to get buildings for your site:

// STEP 1: Define your site (change these coordinates!)
var mySite = ee.Geometry.Rectangle([
  114.130, 22.280,  // Lower left [lon, lat]
  114.145, 22.290   // Upper right [lon, lat]
]); // This covers part of Western District

Map.centerObject(mySite, 15);
Map.addLayer(mySite, {color: 'red'}, 'My Site');

// STEP 2: Get building footprints
var buildings = ee.FeatureCollection(
  'GOOGLE/Research/open-buildings/v3/polygons'
).filterBounds(mySite);

print('Buildings found:', buildings.size());

// STEP 3: Add some analysis (building area)
var buildingsWithArea = buildings.map(function(feature) {
  var area = feature.geometry().area();
  return feature.set('area_sqm', area);
});

// STEP 4: Visualize
Map.addLayer(buildingsWithArea, {color: '0000FF'}, 'Buildings');

// STEP 5: Export to Google Drive
Export.table.toDrive({
  collection: buildingsWithArea,
  description: 'HK_Buildings_Export',
  fileFormat: 'GeoJSON',  // or 'SHP' for Shapefile
  folder: 'GEE_Exports'
});

// Click "Run" in Tasks tab to start export!

After export:

  1. Go to Google Drive → “GEE_Exports” folder
  2. Download the GeoJSON file
  3. Open in QGIS
  4. You now have building footprints with calculated areas!
