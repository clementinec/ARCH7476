# Offering Comparison

This comparison is meant to be blunt enough to guide the rebuild without dismissing useful material from the previous offering.

## Three Versions

| Dimension | DCP / Opening Promise | 2025-26 Live Site | Rebuilt Direction |
|---|---|---|---|
| Primary audience | MArch students | Mixed UG / MArch / PhD | MArch-first, UG-supported |
| Course identity | Generative Design in Architecture | Evidence-Based Generative Design | Studio Evidence Workflows for Generative Design |
| Main object | Studio-linked object, system, component, dataset, or workflow | Tool pathway | Studio decision + evidence workflow |
| Technical promise | IoT, BIM/GIS, light AI, proxy tests, preset simulations | Spreadsheet, GIS, Python; BIM/BEM as literacy | GH / BIM-BEM / GIS / Python / AI-assisted workflow tracks |
| Default technical level | No/low-code default, code-heavy optional | Spreadsheet baseline, GIS/Python optional | Low-code floor plus MArch technical build requirement |
| Assignment logic | Claim -> evidence map -> test plan/pilot -> final package | Audit -> pathway map -> method prototype -> studio evidence package | Total Recall -> workflow selection -> prototype -> retrospective/live application |
| Final output | Practice Case, Research Brief, Object Card, Reproducibility Capsule | 6-10 page studio decision brief, board, artifact, appendix | Decision package with either retrospective redesign or live studio application |
| Student value | Reusable design-evidence method | Better evidence reasoning | Reusable workflow that can feed studio work |

## What To Reduce

| Current pattern | Problem | Replacement |
|---|---|---|
| Repeated stakeholder/privacy discussion | Students experienced it as repetitive | One concentrated ethics and workflow accountability session |
| Long tool-choice survey | Felt like "only telling us choices" | Short tool translation lecture, then immediate project application |
| Same coursework for all levels | MArch students felt under-served | MArch depth requirement and optional UG scaffold |
| Theatrical championship framing | Risks sounding unserious for graduate students | Professional critique, design review, workflow clinic language |
| Generic final evidence package | Can drift away from generative design | Final workflow-backed decision package |

## Rebuilt Course Promise

Short version:

> This course helps architecture students rebuild a studio decision through a concrete, documented workflow using parametric design, simulation, GIS, Python, BIM/BEM literacy, or AI-assisted scripting.

Definition:

> Generative = a workflow that creates or varies multiple design options and evaluates them against explicit criteria.

Long version:

> Students begin by recalling a prior studio decision and auditing what counted as evidence. Across the semester, they learn how design evidence changes when translated through BIM/BEM, GH, GIS, simulation, Python, and AI-assisted workflow building. Each student then builds one small but working workflow and uses it either to redesign a past studio decision or support a live studio decision.

## Course Risk Register

| Risk | Why it matters | Mitigation |
|---|---|---|
| GH/vibe coding becomes chaotic | Tool failures can consume the course | Provide starter definitions, supported plugins, and verification checklist |
| Live studio projects shift mid-semester | Students can lose their evidence target | A1 retrospective anchor; Week 6 A4 branch declaration |
| Undergraduates get overwhelmed | Rebuild is MArch-first | Low-code route remains legitimate with smaller scope |
| MArch students find lectures too abstract | Past issue | Every week includes second-half project application |
| Not enough lecture material | Current slides thin for 2x50 | Use first 50 only for focused lecture/demo; build missing demos flagged in gap log |
