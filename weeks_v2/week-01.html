The recurring engine

Look harder at what you already did

You learn most by examining the reasoning inside work you have already done — not by adding new work. Every week, the same four questions, pointed at that week’s object:

Did What did I actually do, step by step?

Assumed What did I assume at each step?

Risk Where did I not check — where could it break?

Verify What would I verify if I did it again?

The point is not to judge old work. It is to see how its argument was built.

Evidence needs a workflow

  • precedent images can be useful, but rarely prove performance on their own
  • simulation numbers can be precise, but still depend on assumptions
  • survey comments can be rich, but need context before they generalize
  • data only becomes useful when the path from input to decision is legible

A finding is evidence only when someone else can inspect how you got it.

Sometimes evidence is just vibes

A vibe is not useless It is often the first clue that something might matter.

A vibe is not enough by itself It gets stronger only when the next step asks what would confirm, qualify, or challenge it.

For each image next: name the vibe claim, what it does not show yet, and the next evidence move.

Vibe case 1: busy = working?

Let the class answer first

Vibe claim: “This layout works; it feels busy.”

Not shown yet: atmosphere is not a measured use pattern.

Ask for: dwell time, table turnover, circulation pinch points, observation by time period.

Vibe case 2: polished = high performance?

The ad-logic problem

Vibe claim: “This camera is good; the image looks amazing.”

Not shown yet: presentation polish is not performance.

Ask for: controlled comparisons, low-light tests, compression checks, failure cases.

Vibe case 3: calm = safer?

Perception is partial

Vibe claim: “This route is safer; it feels calmer.”

Not shown yet: perceived calm may miss actual risk.

Ask for: lighting levels, pedestrian counts, crossing conflicts, incident records.

Vibe case 4: green = sustainable?

The studio render problem

Vibe claim: “This facade is sustainable; the render is green.”

Not shown yet: visual greenness is not environmental performance.

Ask for: solar exposure, heat gain, daylight, irrigation/maintenance, material data.

Workflow routes, not software shopping

  • GH / parametric — vary design options
  • BIM/BEM / simulation — test performance assumptions
  • GIS — compare spatial conditions
  • Python / notebook — rerun analysis and figures
  • AI-assisted — speed up components, then verify
  • Spreadsheet / low-code — compare ranges and thresholds transparently

Not “which software looks advanced?” but “which workflow makes this decision more defensible?”

Session 2 · Round table

Round table on YOUR evidence

Decision Evidence Variation Output Threshold Action

Upload one rough visual (render, sketch, diagram, table, screenshot), then we work in two modes. feeds A1

Mode 1 — the walk-through (optional, celebrated)

Teach us your strongest tool A volunteer shows the class one tool they know well — uninterrupted, 3–4 minutes. This is teaching, and we treat it as such.

  • not graded as a performance; volunteering earns credit, never penalty
  • the room listens; questions wait for Mode 2
  • no polish required — show the real thing working

Mode 2 — the audit (everyone)

Examine the work, not the person We ask the same question of every artifact, including mine: what does this actually show, and what does it not show yet?

  • the strongest move is naming your own weakest link first
  • we challenge the claim, never your competence
  • volunteers go first; a random draw fills the remaining examples
